# 《说瞎话》代码说明

## 项目概览

《说瞎话》是一个不需要安装依赖、也不需要构建的单页扑克牌游戏。页面结构、样式和全部游戏逻辑都放在 `index.html` 中；浏览器直接打开该文件即可运行。

站点发布时，整个目录按静态资源原样复制到 `/shuoxiahua/`。这是因为 Hexo 配置把 `shuoxiahua/**` 加入了 `skip_render`，避免模板引擎改写游戏页面。

## 文件结构

```text
shuoxiahua/
├── index.html          # 游戏本体：HTML、CSS、JavaScript 均在此文件
├── README.md           # 玩法、角色、版本记录和开发说明
├── 代码说明.md         # 本文档
└── docs/
    ├── strategy.md     # 本地 AI 的策略推演
    └── multiplayer.md  # 联机模式的设计说明
```

## `index.html` 的组成

### 页面与样式

文件前半部分是 HTML 和内嵌 CSS，主要界面包括开始页、单机/联机入口、对手座位、中央牌桌、玩家手牌、操作按钮，以及规则、设置、战绩等弹窗。

配色、牌面、头像和音效都由页面自身生成，没有图片或音频依赖，因此离线打开也能进行单机游戏。

### 基础数据与设置

脚本从 `RANKS`、`SUITS` 等牌面常量开始。每张牌使用一个数字表示，`rk()`、`st()`、`isJoker()` 等函数负责取得点数、花色和大小王状态。

`VERSION` 是页面显示及联机握手使用的版本号。每次发布会影响联机兼容性的修改时，应同步递增它。

`SET` 保存玩法选项，例如大小王是否作为万能牌、一次最多出几张和三家都过后的处理方式。设置通过 `localStorage` 保存在当前浏览器。

### 规则引擎

规则核心集中在以下函数：

- `engineLegal(seat)`：给出指定座位当前允许执行的动作；
- `engineApply(action)`：验证并执行出牌、过牌或抓牌动作，返回供界面播放的事件；
- `serializeGame()`：把当前牌局转为可传输、可保存的数据；
- `loadGame(data)`：从序列化数据恢复牌局。

界面和 AI 都通过同一个动作入口修改牌局，联机时也只有房主运行规则引擎，以避免多套逻辑产生不一致。

### 界面渲染与操作

`render()` 根据当前状态重画座位、牌桌、手牌和操作区。`updateControls()` 决定按钮是否可用，`commitAct()` 和 `commitPlay()` 把玩家操作提交给规则引擎。

规则引擎负责产生确定的结果；翻牌、收牌、台词和动画由 `presentEvents()` 及各类 `present*` 函数按顺序播放。修改规则时应优先改引擎，修改视觉表现时则优先改事件呈现代码。

### 本地 AI

`ROSTER` 定义人物资料和基础牌风，`pickCast()` 每局选出三位对手，`jitterProf()` 给牌风加入少量随机波动。

`aiPlan()` 负责分析手牌和局面并选择动作，`aiChallenge()` 判断是否抓上家，`takeTurn()` 执行 AI 回合。更完整的策略背景见 `docs/strategy.md`。

DeepSeek 是可选的台词增强功能，只参与部分重要场面的斗嘴，不参与出牌决策。API Key 只写入玩家浏览器的 `localStorage`；请求失败时会自动使用内置台词。

### 本地存储

页面使用浏览器 `localStorage` 保存：

- `sxh_set`：玩法、声音和台词设置；
- `sxh_mem`：跨局战绩与行为记录；
- `sxh_cast`：偏好的 AI 人物；
- `sxh_name`、`sxh_ava`：联机昵称和头像；
- `ds_key`：用户自己填写的 DeepSeek API Key。

清除浏览器站点数据会一并清除这些设置和战绩。

### 联机模式

联机代码从 `loadPeerLib()` 开始，使用 PeerJS 建立点对点连接。房主保存完整牌局并运行规则引擎，其他玩家只发送动作、接收自己的可见状态和公共事件。

主要流程如下：

1. `hostRoom()` 创建四位房号，`joinRoom()` 加入房间；
2. `hostMsg()` 校验加入者版本并处理消息；
3. `startNetGame()` 在房主端开局；
4. `netBroadcastEvs()` 广播公开事件，`envelope()` 为每位玩家生成对应的可见状态；
5. `clientApply()` 在客机更新状态并播放事件。

联机依赖外部信令和 PeerJS CDN，因此需要网络；单机逻辑不受影响。详细架构见 `docs/multiplayer.md`。

## 本地开发

最简单的方式是直接用浏览器打开 `index.html`。如果需要测试联机、网络请求或线上路径，可从博客根目录运行：

```bash
npm run server
```

随后访问 `http://localhost:4000/shuoxiahua/`。

修改后的基本检查项：

1. 单机可以开始、出牌、过牌、抓牌并正常结束；
2. 刷新页面后设置和战绩仍在；
3. 手机宽度和矮屏幕下没有按钮溢出；
4. 两个浏览器窗口能用同一房号加入并完成若干回合；
5. 页面标题旁的版本号与 `VERSION` 一致。

## 发布与维护

博客构建命令为：

```bash
npm run build
```

构建完成后应存在 `public/shuoxiahua/index.html`。

维护时注意：

- 不要把真实 API Key 写进 `DEFAULT_KEY` 或提交到仓库；
- 修改状态结构或联机消息格式时，同时考虑 `PROTO` 和 `VERSION` 的兼容性；
- 规则变化应继续统一通过 `engineApply()` 落地；
- 新增外部资源会改变当前的离线可玩特性，应明确评估后再引入。
