Desk Lamp Motor and Lighting Controller

Sep 2026 to present   Sole hardware and firmware designer   Board tested, firmware running   Source on GitHub

Motor and lighting controller for a lamp-shaped companion robot prototype. It takes commands from a Linux main board over UART and drives the robot's joints and lights.

STM32F4074-layer PCBFreeRTOS8x H-bridge24 V inputEasyEDA ProPython tools

Hardware

  • 24 V input with fuse, P-MOS reverse-polarity protection and TVS; three buck stages for motors, the Linux board and logic, plus a 3.3 V LDO
  • 8 RZ7899 H-bridge motor channels, 6 potentiometer inputs for joint angle, 7 lamp PWM channels
  • Stackup: signal, solid GND plane, power plane split into 24 V, 12 V and 5 V regions, signal; motor and lamp power kept to the board edges, away from PWM and feedback lines

Firmware and tools

  • Binary UART protocol to the main board: framing, CRC16, duplicate filtering, timeout and error recovery
  • Joint calibration stored in on-chip flash and restored at power-up
  • Watchdog; on fault, e-stop or heartbeat timeout all outputs stop until explicitly re-armed
  • Protocol and control layers unit-tested on PC with gcc; Python GUI for driving all motors and lights on the bench

8-Channel PT100 Over-Temperature Alarm Controller

Contract project, Jul 2026 to present   Sole hardware and firmware designer   v1 delivered v2 assembled, testing   Source on GitHub

Fire-protection controller for kitchens and ducts. When any of eight temperature channels passes its threshold, it sounds the alarm, stops the fan, shuts the gas valve and closes the fire damper. Version 1 was delivered to the customer site in July 2026.

STM32F103RS485 Modbus RTURelay controlFail-safe designOrange Pi Linux

Version 1, delivered

  • Carrier board for an STM32F103 core module, buck and RS485 modules; 7-segment displays, setting keys, indicators and four relay outputs
  • Reads a PT100 acquisition card over RS485 Modbus RTU
  • Alarm latches until manual reset, then a 3-minute hold-off so residual heat at the sensors does not retrigger it
  • Relays release on power loss and the damper stays open, so a controller failure never blocks other equipment
  • Installation and maintenance manual for the site electricians

Version 2, assembled

  • Single integrated board: STM32F103, RS485 transceiver, four 250 VAC 10 A relays
  • Isolation slot between the mains relay area and the low-voltage logic
  • 24 V to 5 V 5 A supply and a UART link for an Orange Pi Linux gateway
  • Gateway for HTTPS data upload and alarm video recording, software in progress

Tremor Assessment and Intervention Glove

SRTP research project, Prof. Yun Pan's lab, Feb 2026 to present   Sole board designer   v1 layout complete v2 revision in progress   Source on GitHub

A wearable glove that measures hand tremor and applies transcutaneous electrical stimulation. Two stacked boards connected over SPI. Research prototype, no medical claims.

nRF52832 BLENNC61214-layer and 6-layer PCBHigh-voltage layoutEasyEDA scripting

Boards

Stimulation board layout

All images on this project are 3D renders and layout exports of the first revision. The boards are being revised before fabrication.

Main board

  • nRF52832 with 2.4 GHz antenna matching network
  • Eight I2C sensor ports for finger sensors, wrist IMU and magnetometer, with switched sensor power
  • USB battery charging and battery voltage sensing

Stimulation board

  • NNC6121 with on-chip boost up to 55 V, two stimulation channels, electrode-off detection and an e-stop button
  • Stackup: top, GND, signal, signal, GND, bottom; 0.6 mm clearance rule for all high-voltage nets
  • High-voltage, analog and digital grounds split and joined at a single point; boost and output stages kept away from the digital area
  • Python scripts on the EasyEDA API for rule-aware routing and connectivity checks; stackup, rules, part choices and final review done by hand

ESP32-C3 IoT Clock

Oct 2025 to Nov 2025   Sole hardware and firmware designer   Course project, team of two   Completed   Source on GitHub

Desktop assistant for an AIoT course. I designed and built the device, wrote all of its firmware, connected it to Huawei Cloud and wrote a WeChat Mini Program to control it remotely. My teammate built the YOLOv5 camera node on an Orange Pi.

ESP32-C3PlatformIOFreeRTOSMQTTHuawei Cloud IoTDAWeChat Mini Program

Device

  • ESP32-C3 with a 1.69 inch TFT, rotary encoder menu, buzzer, WS2812 LEDs, DS18B20 temperature sensor and photoresistor
  • Wi-Fi setup through a SoftAP web page; NTP time sync, 17 watch faces and weather
  • 20 online info pages from web APIs, including exchange rates, GitHub trending, stock prices and the ISS position
  • Alarm, countdown, Pomodoro timer and stopwatch; 88 songs on the buzzer with LED effects; four small games
  • PC monitor showing CPU and GPU temperature and load and RAM usage, streamed from the PC over USB serial
  • Background FreeRTOS tasks for MQTT, sensor sampling, alarm checks, music playback and the PC data serial link

Cloud and app

  • Temperature, light and PC data reported to Huawei Cloud IoTDA over MQTT
  • Cloud commands to set LEDs, pick songs and set alarms
  • WeChat Mini Program that signs in through Huawei Cloud IAM, reads the device shadow and sends commands
